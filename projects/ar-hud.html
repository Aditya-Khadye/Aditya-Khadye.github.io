A live telemetry overlay for simracing on visionOS. The app bridges a UDP data stream from a simulator, parses raw binary packets on the fly, and pins a SwiftUI HUD at a fixed point in 3D space using RealityKit anchoring.

Code walkthrough
Why this code

The binary OutGauge protocol is a C struct sent over UDP — bytes at specific offsets map to speed, RPM, gear, etc. The failable init?(data:) is the parsing gate: if the packet is too short or malformed, the struct simply doesn't exist. No error handling boilerplate downstream, no sentinel values to check. The caller gets an OutGaugePacket or nothing.

withUnsafeBytes { buf.load(fromByteOffset:as:) } reads raw memory layout matching the C struct byte-for-byte. It's the Swift equivalent of a C cast — necessary when you're talking to a protocol you don't own. The UInt32(littleEndian:) wrapping handles endianness explicitly rather than relying on platform defaults.

Why this code

hud.position = [0, 1.35, -1.0] is not a magic number — it comes from Apple's visionOS HIG: 1.35 m above the floor puts the overlay at eye level for an average seated user, and −1.0 m forward places it at a comfortable reading distance without blocking the view of the room.

The Attachment(id: "hud") API is the bridge between SwiftUI and RealityKit's 3D space. The SwiftUI view tree (VStack, Text, etc.) lives in the 2D world but gets anchored as a 3D entity. The @EnvironmentObject chain means the HUD auto-updates whenever TelemetryClient publishes new speed/RPM — no polling loop, no manual refresh.
