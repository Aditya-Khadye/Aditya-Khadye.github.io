The Script
Gap

A research tool for The Readability Consortium (TRC) at UCF — identifying which of the world's writing systems are most underserved by current typeface libraries. Combines web exposure data (Google CrUX / BigQuery), font support counts, visual diversity scores (ViT embeddings), and glyph complexity metrics — then runs K-Means clustering to tier scripts by urgency. TRC's industry stakeholders include Google, Adobe, and Monotype.

Code walkthrough
Why this code

Web exposure spans orders of magnitude — Arabic gets hundreds of millions of page views; Telugu gets tens of thousands. Without log-scaling, K-Means distance is dominated by the two count features, and the other dimensions (visual complexity, font diversity) contribute almost nothing to cluster assignment. np.log1p compresses the range while preserving relative ordering.

StandardScaler after log-scaling is the second step: even after logging, exposure and support still have different scales. Z-score normalization ensures all four indices — exposure, support, complexity, diversity — pull equal weight in the Euclidean distance calculation that K-Means uses. The code's inline docstring explains the reasoning, so someone running this six months later doesn't have to re-derive it.

Why this code

With only 8 data points (8 writing systems), over-clustering is a real risk — k=4 would give clusters of 1–2 scripts, too granular to be meaningful. Silhouette score automatically penalizes both under-fitting and over-fitting, so it's used to pick k from the range 2–5 rather than fixing k up front.

The "prefer simpler if within 0.05" tie-breaker in select_k() is a principled Occam's razor: if k=2 achieves nearly the same silhouette as k=3, the simpler model is more defensible to present to stakeholders. The 0.05 threshold was chosen to be meaningful but not so tight that it always forces the minimum k.

Why this code

Three backbone models were benchmarked — ResNet18 (similarity range 0.83–0.91), ConvNeXt-Tiny (0.81–0.93), and ResNet50 (0.75–0.98). ResNet50 was chosen because it produced the widest and most stable spread, which matters here: we need the model to actually distinguish between Latin (well-represented) and scripts like Telugu (sparse, visually distinct). A compressed range would collapse that signal.

L2 normalization after the global average pool converts the 2048-dim embedding to a unit vector, so the dot product between two embeddings equals cosine similarity — a geometry-independent measure that doesn't penalize shorter vectors. Each font is averaged over all its rendered glyphs, so a single font's "embedding" represents the overall visual character of that writing system's typeface, not just one glyph.
