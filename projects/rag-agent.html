Code walkthrough
Why this code

Incremental ingestion is the main design decision here. The naive approach — load everything, embed everything, write a new index — works fine the first time but breaks down when your document set grows: re-embedding 10,000 documents to add 5 new ones is wasteful. The if os.path.exists(index_path) branch loads the existing FAISS index and calls vectorstore.add_documents(chunks) instead of rebuilding from scratch.

The dual embedding provider (OpenAIEmbeddings if a key is present, HuggingFaceEmbeddings otherwise) keeps the pipeline portable: it works locally without any API credentials. The key insight is that both providers share the same LangChain interface, so the rest of the code doesn't need to know which one is active.

Why this code

create_tool_calling_agent instead of RetrievalQA is the architectural choice that matters most. A standard RAG chain always retrieves — it doesn't decide whether retrieval is needed. A tool-calling agent treats search_documents, retrieve_document_info, and summarize_text as optional tools it can call selectively. If the question is answerable from context, it doesn't waste a vector lookup.

The system prompt's "Always cite which document and section" line is load-bearing. Without an explicit instruction, LLMs frequently omit citations even when they have the source data — they'll answer correctly but present it as general knowledge. The MessagesPlaceholder("chat_history") allows multi-turn conversation while keeping the prompt template clean and the agent stateless.
